# LOCACTION

**[Открыть веб-демо](https://alexaid1.github.io/locaction/)**

LOCACTION помогает владельцу стрит-ритейла выбрать помещение в Москве до подписания аренды. Пользователь отмечает точку на карте, описывает бизнес и получает карточку: оценку места, прогноз работы на год (когда модель подтверждена) и потоки людей вокруг с пометкой «оценка, не замер».

## Что умеет приложение

1. **Точка.** Карта Москвы раскрывается на весь экран по кнопке, по первому касанию или при поиске адреса. Подсказки адресов идут из своего индекса зданий OSM (150 тыс. адресов, без внешних сервисов). Клик по зданию поднимает его в объёме и открывает мини-карточку: тип, расстояние до метро, площадь контура, кнопка «Подтвердить».
2. **Бизнес.** Анкета из плиток (28 категорий стрит-ритейла) и чипов: формат, средний чек, часы, аудитория, площадь, своя точка или сеть. Можно описать бизнес своими словами: разбор показывает «Мы поняли так», и любой параметр можно поправить.
3. **Карточка.** Карта переходит в ночной 3D-вид: объекты влияния всплывают метками, к точке тянутся линии (зелёные помогают, красные мешают), по улицам течёт «дым» потоков, переключатель «утро / день / вечер». Панель показывает оценку места, прогноз на год или честное «пока недоступен», поток мимо и показатели. Наведение на показатель подсвечивает его объекты на карте.
4. **Разбор от ИИ, сравнение до 5 точек, PDF.**

Состояние хранится в адресе страницы после `#`, ссылкой на карточку можно поделиться. Прежний сравнительный отчёт по трём адресам в Митино открыт как [пример](example.html).

## Сервер расчёта и заглушка

Интерфейс говорит с сервером только через [api/client.mjs](api/client.mjs). Адрес сервера - одна строка в [config.mjs](config.mjs):

```js
export const API_BASE = 'stub';                       // встроенная заглушка
// export const API_BASE = 'https://api.locaction.ru'; // настоящий сервер
```

Контракт запросов и карточки - [contract/README.md](contract/README.md): `POST /v1/parse`, `POST /v1/card`, `POST /v1/explain`, схемы JSON и примеры. Проверка любого JSON по схеме: `python tools/check_contract.py card файл.json`.

Заглушка ([api/stub/](api/stub/)) отвечает строго по контракту:

- **Карточка** - временный расчёт по [демо-методике v2](methodology.mjs), обобщённой на 28 категорий, по своему слою объектов OSM [map/poi/](map/poi/) (снимок 23.11.2026, без внешних запросов). Прогноз - `not_validated`, потоки - `illustration` по улицам подложки. Если слой не загрузился, карточка открывается на примерных данных с плашкой.
- **Разбор текста** - правила по ключевым словам вместо LLM.
- **Разбор от ИИ** - шаблон только из чисел карточки, с той же проверкой «нет чужих чисел», что и на сервере.
- `?forecast=validated` в адресе показывает, как выглядит подтверждённый прогноз, с плашкой «Пример состояния».

## Пример по Митино и демо-методика v2

[Пример](example.html) сравнивает три адреса в Митино для кофейни навынос:

| Место | Адрес | Индекс из 100 |
|---|---|---:|
| 1 | Дубравная улица, 36 | 75,2 |
| 2 | Митинская улица, 40 | 72,1 |
| 3 | Дубравная улица, 40, корп. 2 | 62,4 |

В примере Митинская, 40 ближе к метро, а у Дубравной, 36 меньше учтённых кафе в радиусе 300 м. При текущих весах преимущество по второму фактору перевешивает.

В примере работает 2D-карта Москвы. Кнопка «К демо-адресам» приближает Митино, а метки показывают адрес и индекс и выделяют связанные контуры. На крупном масштабе можно открыть карточку здания и переключить раскраску по типам. Иллюстрация Митино служит запасным видом при отказе карты. Отдельный эксперимент с ML ведётся вне этого репозитория. Пользовательский индекс рассчитывается по описанным ниже правилам.

## Как считается индекс

Демо-методика **v2** складывает вклады пяти факторов. В таблице указан максимальный вклад каждого фактора при полном наборе данных.

| Фактор | Макс. баллов | Правило |
|---|---:|---|
| Кафе и кофейни в 300 м | 25 | При подтверждённом нуле вклад равен 25. Каждое учтённое кафе уменьшает его на 2,5 балла, минимум - 0. |
| Расстояние до входа в метро | 35 | До 75 м по прямой вклад максимальный, между 75 и 700 м он линейно снижается до нуля. |
| Остановки в 300 м | 15 | Вклад растёт линейно до шести посадочных точек. |
| Офисные объекты в 500 м | 10 | Вклад растёт линейно до 20 объектов. |
| Объекты притяжения в 300 м | 15 | Вклад растёт линейно до 12 объектов. Учитываются супермаркеты, ТЦ, фитнес-центры, клиники и больницы. |

Если значение одного фактора отсутствует хотя бы у одного адреса, фактор исключается из оценки всех адресов, а веса оставшихся пропорционально пересчитываются до 100. Отчёт помечает такой рейтинг как предварительный и показывает охват расчёта. Подтверждённый ноль участвует в оценке. Если общих факторов нет, места не присваиваются. Итоги округляются до десятых, одинаковые отображаемые итоги делят место.

Веса, пороги и радиусы выбраны для демонстрации и пока не откалиброваны по результатам кофеен. Индекс помогает сравнивать адреса в одном отчёте. Выручка, вероятность закрытия, аренда, видимость входа и фактический пешеходный поток в расчёт не входят.

## Источники данных

Кафе взяты из московского среза OpenStreetMap от **17 ноября 2026 г.** Адреса и остальные объекты взяты из выгрузки по Митино, полученной **22 ноября 2026 г.** В [демо-данных](demo-data.json) сохранены координаты, показатели, сведения об источниках и учтённые объекты.

Категория кафе опирается на тег `amenity=cafe` и включает разные типы заведений. Расстояния измеряются по прямой от расчётной точки здания. Покрытие OpenStreetMap и актуальность отдельных объектов могут различаться. [© Участники OpenStreetMap, ODbL](https://www.openstreetmap.org/copyright)

## Локальный запуск

Нужен Python 3. Из корня репозитория выполните:

```sh
python tools/preview.py --port 8092
```

Откройте [локальное превью `/locaction/`](http://127.0.0.1:8092/locaction/). Сервер поддерживает HTTP Range для архива карты. Без WebGL вместо карты показывается иллюстрация Митино, поиск адреса и карточка без 3D работают.

## Сборка публичной подложки и контуров

Из корня репозитория в PowerShell, с Python 3.11–3.13:

```powershell
python -m venv .venv-map
.\.venv-map\Scripts\python.exe -m pip install -r tools/requirements-map.txt
curl.exe -fL 'https://download.openstreetmap.fr/extracts/russia/central_federal_district/moscow-latest.osm.pbf' -o "$env:TEMP/locaction-moscow.osm.pbf"
.\.venv-map\Scripts\python.exe tools/export_osm.py "$env:TEMP/locaction-moscow.osm.pbf" --ao "D:\HSE\ГИП\map\ao.geojson"
```

Скрипт формирует `map/osm-basemap.pmtiles` и `map/buildings.pmtiles`. Он работает с геометриями OSM, переводит их в EPSG:3857 и хранит площадь контура, вычисленную в EPSG:32637. Параметр `--ao` включает сверку охвата 12 округов без включения `ao.geojson` в архивы. URL `latest` меняется со временем. Для воспроизведения опубликованного снимка используйте исходный PBF с контрольной суммой из [map/SOURCES.md](map/SOURCES.md).

Для локальной проверки адресного слоя запустите `python tools/audit_buildings.py "D:\HSE\ГИП\map\ALL_MOSCOW.gpkg" "D:\HSE\ГИП\map\ao.geojson"` в среде с установленными зависимостями. `tools/export_basemap.py` оставлен для локальной пересборки прежней подложки из `msk_basemap.gpkg`.
